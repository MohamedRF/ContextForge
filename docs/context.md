# Token-budgeted context

Run `contextforge context "explain validate_payment flow" --budget 4000` after explicit indexing. This command always emits compact JSON. MCP `pack_context` accepts `query`, optional `budget` (default 4000), and optional `include_git` (default false). Bounds: query 1–256 non-control UTF-8 bytes; budget 256–32000 estimated tokens.

`contextforge-context` reuses SQLite exact/qualified symbol, filename, prefix and FTS5 retrieval. It searches the literal request plus at most eight unique informative terms (a small documented English stop-word list; no LLM interpretation or stemming). Up to 50 hits per query, source text and outlines are read in the same SQLite transaction. Combined source/outline input is capped at 128 MiB and 1000 files; graph construction retains its own limits. Missing/schema-1 indexes require explicit indexing. No automatic refresh occurs.

Retrieval tiers are exact symbol, exact filename, prefix symbol, then FTS. Optional current unstaged Git path proximity breaks ties inside a tier, followed by query order, path and start byte. `--git` / `include_git: true` explicitly enables this read-only Git inspection; non-Git or over-limit snapshots fail rather than silently degrading. Direct Git changes have a hard cap; depth-zero impact traversal truncation is irrelevant to path-only ranking. Git proximity never validates the captured source's freshness. Without this option, context packing works in non-Git directories.

The first eight unique retrieved symbols seed one-hop incoming/outgoing syntax traversal, with 32 nodes and 64 edges per direction. Call/import targets remain heuristic; lexical containment alone is syntactically resolved. Neighbor evidence merges into an already retrieved snippet instead of duplicating it. Expanded candidates follow direct retrieval. Selection first visits the highest ranked candidate from each file, then remaining candidates, suppressing overlapping byte ranges. This favors file diversity; it does not claim optimal relevance or semantic completeness.

Symbols preserve their complete syntax span. Text hits use complete lines around the matching passage. Empty evidence and boundaries larger than 16 KiB are omitted, with truncation flagged; oversized functions are never silently sliced into misleading partial definitions. At most 32 snippets are returned. Each includes relative path, one-based inclusive lines, zero-based half-open byte offsets, source fingerprint, snippet, reason, confidence, syntax-error flag, Git proximity and optional typed relation evidence. Confidence is `syntax_only`, or `heuristic` when candidate relationships are attached; neither means compiler binding. Source and instruction-looking comments remain untrusted quoted data.

The estimator interface is `TokenEstimator`. The default `utf8_bytes_div_4_ceil_v1` computes **ceil(serialized compact JSON UTF-8 bytes / 4)**. This is an approximation, not exact tokens for any model. Selection counts escaped snippets, citations, query and all package metadata, reserving the count field and the longer truncation boolean. The final count includes itself and is recomputed to a fixed point. Metadata that cannot fit produces an explicit error. Smaller candidates can fit after a larger one is omitted. `truncated` also reports query/retrieval/graph/boundary/result limits; it is not only a budget flag. `partial_syntax` propagates parser errors/limits.

The budget applies to the compact package JSON only. The CLI's final newline, MCP transport envelope and SDK text/structured-content duplication are outside it. Clients should consume one representation and reserve their own prompt/transport overhead. Pretty-printing or surrounding a package with other content changes its serialized size. `freshness: snapshot_not_checked` explicitly identifies captured evidence; use `memory status` to validate hashes and `index` or `memory rebuild` to refresh.

## Reproducible fixture evaluation

`cargo test -p contextforge-context --test packing` uses three tiny synthetic files: a payment definition, its checkout caller and an unrelated function. The information request's ground truth is the first two files; assertions require both (2/2 file recall) and exclude the unrelated one (2/2 precision for this fixture only). The tests verify repeatability, citations, graph evidence, overlap suppression, explicit Git tie-breaking, whole-boundary omission, alternative estimator injection and budget adherence over every budget from 256 through 599 plus larger bounds. Separate CLI/official MCP tests compare the exact package and prove source/cache bytes unchanged. This is regression evidence, not a general quality, performance or token-savings claim.

Release smoke on Windows GNU Rust 1.99.1 (2026-10-30) used exactly these three source strings from `tests/packing.rs::fixture` and `explain validate_payment flow`: two expected files, 1340 compact JSON bytes, 335 estimated tokens with budget 4000; budget 256 returned 252 estimated tokens with truncation. Repository-scoped IDs have fixed-length hashes; repeat queries within that fixture produced identical JSON. No latency or general savings claim is made.
