# Persistent structural knowledge

ContextForge reuses the schema-2 SQLite source/outline/symbol inventory rather than maintaining a second cache of prose summaries. Source paths/languages form a module inventory; source-linked outlines retain syntactic symbols and occurrences. Graph relationships are derived from these persisted outlines per request. No agent chats, generated summaries or approved-note facility are stored. The cache can contain source-embedded secrets because it stores source text; keep it private.

`contextforge memory status` is read-only and emits JSON. It compares every eligible current file's SHA-256 with one consistent stored snapshot, within existing discovery and 64 MiB source bounds. Files include relative path, language, captured fingerprint, validity and a symbol count only for valid schema-2 evidence. Added files, edits, deletion, renames and new ignore rules produce `stale`; stale file symbol counts are null. Missing caches report `missing` without creating anything. Schema 1 is stale until explicit migration. Truncated inventories or read failures fail closed. `validated_at_read` describes hashes observed during that operation, not a lock against subsequent filesystem edits. Other search/graph/context contracts continue to expose explicitly labeled captured snapshots.

`contextforge memory clear` explicitly deletes this repository's source, outline, symbol and FTS rows in one immediate transaction, preserving configuration, schema, identity and source files. Missing caches are a no-op; no directories are recursively removed. This is a logical reset, **not forensic secure erasure** of database free pages, journals or filesystem backups. It cannot fix an unknown/corrupt schema; those bytes are preserved with an error. Concurrent indexing and clearing serialize through SQLite; a later explicit index can repopulate the cache.

`contextforge memory rebuild` captures current eligible sources and reparses all structures, including unchanged files. It shares indexing's bounded preparation, migration, concurrency checks and atomic commit. Preparation or write failures preserve the previous snapshot; there is no delete-before-rebuild window. Ordinary `index` continues to parse only changed files. Root identity namespaces and database identity checks isolate repositories, including shared external index roots.

The persistent format remains schema 2; this slice changes lifecycle commands, not table contracts. Unknown versions/corruption fail closed. Parser/schema changes require deliberate versioning and reindexing; no arbitrary stored note can act as a privileged instruction. Tests cover separate CLI processes, stale hash detection, addition/removal, forced reparsing, clear/rebuild rollback, corruption preservation and the existing external-cache isolation/migration suite.
