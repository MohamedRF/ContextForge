# Source snapshot storage (schema 2)

`contextforge init` creates configuration; `contextforge index` explicitly captures supported UTF-8 source files. CLI status and doctor inspect existing metadata read-only. MCP tools never create or refresh an index.

Cache path is `<index_root>/<sha256(native-canonical-root)>/index.sqlite`. A relative index root is beneath `.contextforge`; an absolute root explicitly selects external metadata storage. Canonical root identity is platform-local, not a portable repository identifier. Moving a repository creates a different cache namespace. Repository identity is also checked inside the database.

External cache paths must have no linked ancestors. Use the canonical directory path when your system provides aliases, such as macOS `/var` pointing to `/private/var`. This keeps cache-path validation consistent with the no-linked-metadata policy.

SQLite uses bundled SQLite through rusqlite 0.41.1, parameter-bound values, a 2-second busy timeout and `trusted_schema=OFF`. Every update uses one immediate transaction. Source discovery, reads and changed-file parsing happen before that transaction. The preparation connection permits hot-journal recovery during explicit indexing. All eligible files are read and SHA-256 hashed; only added/changed records are written and reparsed (schema-1 upgrades backfill all syntax). No timestamp-only shortcut can miss a same-length edit. Deleted/ignored/renamed files lose obsolete source/syntax/FTS rows (rename is delete+add). This is incremental database writing and changed-file full parsing, not incremental source reading or Tree-sitter tree editing.

Schema 1 has `repository(singleton, identity)` and `files(path, language, fingerprint, content, bytes)`. Schema 2 adds `outlines(path, payload, partial)`, `symbols(id, path, name, qualified_name, kind, start_line, end_line, start_byte, end_byte, contains_errors)` and standard FTS5 `source_fts(path UNINDEXED, content)` with Unicode61. It indexes symbol name, qualified name and path. Outlines retain source fingerprint, parents, visibility, bounded signatures, syntax error/truncation flags and unresolved occurrences. FTS keeps its own source copy to avoid external-content trigger consistency risks; cache size increases accordingly.

Paths are relative. Empty schema 0 initializes schema 1, then upgrades to 2; existing schema 1 upgrades additively on explicit `index`. New derived rows are backfilled from the captured sources within the same transaction. `PRAGMA user_version=2` commits with all source/outline/symbol/FTS updates. Migration and update failures roll back completely; unknown versions/nonempty unknown schemas/corrupt databases are preserved and rejected. Future parser/model changes require deliberate versioning and backfill. Existing cached evidence is not trusted operational instruction. Read-only status accepts versions 1/2; search requires 2. Older binaries reject version 2 rather than silently misreading it.

Changed files are parsed before the write lock. If another writer changes a previously unchanged file in between preparation and commit, missing prepared syntax aborts the whole transaction with an explicit retry error. Concurrent writers with identical source snapshots can converge without duplicates. The JSON index report adds `parsed_files` (actual parser invocations, possibly speculative) and `partial_files` (stored error/truncated outlines). Parser truncation is per-file and does not prevent full-source FTS capture. See [parser coverage](parsing.md) and [search](search.md).

Discovery cap: 1000 eligible files, 10000 yielded entries and depth 64. Total snapshot text cap: 64 MiB; per-file cap: configured maximum (default 1 MiB, maximum 16 MiB). Truncation and read failures prevent all database updates, so a partial inventory cannot delete undiscovered records. A changing file that becomes missing/binary/oversized during capture aborts the snapshot. Files may change after capture; this is a snapshot, not a live index. Status explicitly says `freshness: "not_checked"` until a future validity check runs.

Indexing stores source bodies, potentially including source-embedded secrets, locally. Do not share cache directories. Newly created cache directories use mode 0700 on Unix; Windows inherits directory ACLs. Existing permissions are not rewritten. Never include metadata in public fixtures/commits. Symlinks/reparse points are rejected for cache directories/database/known SQLite sidecars and every source path component. Unix cache files/sidecars with multiple hard links are rejected. Database/sidecar size, SQL row/statement/attachment and read-VM-work limits are documented in [security](security.md). Handle-relative race protection, Windows hard-link/ACL validation, hostile-cache tampering and new-source cross-platform permission verification remain hardening work. Do not use actively hostile repositories or attacker-controlled caches.

Regression tests cover cold/unchanged indexing, same-size edits, deletion/rename, newly ignored/binary files, persistence, concurrent writers, rollback on an injected write failure, abrupt writer-process exit, future versions, corruption, truncation and external-cache repository isolation. The next explicit index can recover SQLite's interrupted rollback journal; read-only status does not promise hot-journal recovery. A generated public 100-file Rust fixture supplies a reproducible [local baseline](benchmarking.md); these results are not a general performance claim.

Graph queries export at most 1000 schema-2 outlines/64 MiB JSON in one read transaction and derive candidate relations in memory; no new persistent format is introduced. Git impact independently captures Git/source snapshots and never reads or refreshes this SQLite index. Graph call/import targets are heuristic or unknown; details in [graph](graph.md) and [impact](impact.md).

Context retrieval reads search hits, source and outlines in one read transaction, capped at 128 MiB combined input. Structural [memory commands](memory.md) validate hashes or explicitly clear/rebuild the same schema-2 records. Clearing is transactional logical deletion, not forensic erasure. Rebuilding reparses even unchanged sources, committing only after complete preparation succeeds.
